# Packaging

`linux/` turns the Linux desktop tarball (`koalino-linux-ARCH-VERSION.tar.gz`, ARCH `x86_64` or
`arm64`) into distribution packages (#164, #175). Each script only repackages the release build:
nothing is compiled or downloaded. The scripts read the architecture from the tarball's name.
The `.deb` is `amd64` or `arm64`, the `.rpm` `x86_64` or `aarch64`, and either can be built on
any machine.

| File | What it does |
| --- | --- |
| `linux/build-deb.sh` | `.deb` for Debian 13+ and Ubuntu 24.04+, with `dpkg-deb` |
| `linux/build-rpm.sh` | `.rpm` for Fedora, openSUSE and other RPM distributions, with `rpmbuild` |
| `linux/build-flatpak.sh` | single-file `.flatpak` bundle on the Freedesktop 24.08 runtime |
| `linux/io.github.capannone_dev.koalino.desktop` | menu entry; `StartupWMClass` is the GTK application ID, so the window gets the icon |
| `linux/io.github.capannone_dev.koalino.metainfo.xml` | AppStream description for software centres |
| `linux/io.github.capannone_dev.koalino.yml` | Flatpak manifest (the script fills in the tarball's path and SHA-256) |
| `linux/koalino-128.png`, `koalino-192.png`, `koalino.svg` | icons, generated by `branding/make-icons.sh` |

The `.deb` and `.rpm` install the app in `/opt/koalino`, `koalino` in `/usr/bin`, and the menu
entry, icons and AppStream file under `/usr/share`. Dependencies are the system libraries the
bundle does not carry: GTK 3, ALSA, libstdc++ and xdg-utils, plus a keychain as a
recommendation.

## Windows installer and portable .exe

`windows/` turns the Windows release zip (`koalino-windows-ARCH-VERSION.zip`, ARCH `x86_64` or
`arm64`, #176) into two downloads, with [NSIS](https://nsis.sourceforge.io/) (zlib licence), whose
`makensis` runs on Linux (Debian package `nsis`):

- an installer, `koalino-windows-ARCH-VERSION-setup.exe`;
- a portable `.exe`, `koalino-windows-ARCH-VERSION-portable.exe` (#177), which runs Koalino without
  installing it.

| File | What it does |
| --- | --- |
| `windows/build-installer.sh` | `build-installer.sh <zip> <VERSION> <output-dir>`: unpacks the zip and runs `makensis` for both downloads |
| `windows/koalino.nsi` | the installer script |
| `windows/koalino-portable.nsi` | the portable `.exe`'s script |
| `windows/architecture-check.nsh` | the check both share: each refuses a computer of the other architecture |
| `windows/wizard.bmp`, `header.bmp` | the wizard's side panel and header, generated by `branding/make-icons.sh` |

The installer needs no administrator rights: it installs for the current user into
`%LOCALAPPDATA%\Programs\Koalino`, adds Start menu and desktop shortcuts, and registers an
uninstaller in Settings → Apps. Installing again upgrades in place, and asks to close Koalino
first if it runs. Uninstalling removes the program, its shortcuts and the browser extension's
registration, and keeps the meetings in `%APPDATA%\capannone-dev\Koalino`. `/S` runs either silently.

Both check the computer's architecture before doing anything:

- The ARM64 downloads refuse x64 Windows.
- The x64 downloads ask first on Windows on ARM, where they would run under emulation.

The portable `.exe` installs nothing. On first start it unpacks Koalino into
`Koalino VERSION ARCH` beside itself, or into `%LOCALAPPDATA%\Koalino Portable` when that folder
can't be written, then starts it. Later starts open the unpacked copy at once; a marker file,
written last, makes an interrupted unpacking start over. Meetings live in the same folder as the
installed app's.

Silently (`/S`) the x64 installer goes ahead there.
