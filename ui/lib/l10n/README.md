# Translations (Issue #124)

Koalino's menus and messages are available in ten languages: English, Italian, Spanish, French,
German, Portuguese, Simplified Chinese, Japanese, Russian and Arabic (right to left). The app
follows the system language; Settings → *App language* overrides it on this device.

## Contents

- `app_<lang>.arb`: the messages, one file per language, in ICU syntax. `app_en.arb` is the
  template: it alone carries the `@key` descriptions and placeholder declarations.
- `app_localizations*.dart`: generated by `flutter gen-l10n` (configured in `ui/l10n.yaml`). Do not
  edit them by hand.
- `l10n.dart`: the global `l10n` getter every widget and controller reads, `useAppLocalizations`,
  which the root scope calls, and `formatDatePattern`, which formats dates in the language in use.

## How it fits

`presentation/app_localization_scope.dart` sits in `MaterialApp.builder`. It sets `l10n` from the
resolved locale, and rebuilds every screen when the language changes. Text therefore needs no
`BuildContext`, so controllers can word their messages too. Widgets tested on their own,
without that scope, show English.

## Adding or changing a message

1. Add the key to `app_en.arb` with an `@key` entry. Declare its placeholders there; a count uses
   `{count, plural, ...}`.
2. Add the same key to every other `app_<lang>.arb`, keeping the placeholder names.
3. Run `flutter gen-l10n` in `ui/`, then use `l10n.yourKey` in the code.
4. `test/app_language_test.dart` fails if a language lacks a key or a placeholder.

The translations were machine-made, so native speakers should review them. Kept in English on
purpose:
- brand and product names;
- the GPL licence notice;
- Whisper's list of transcription languages;
- messages the Rust core returns verbatim for developers.
